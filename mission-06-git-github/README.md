### Basic Git workflow
| Git operation | What it does |
|---|---|
| `git status` | Reports modified, staged, and untracked files. |
| `git add <file>` | Places selected changes in the staging area. |
| `git commit -m "message" | Records the staged snapshot in local repository history. |
| `git diff` | Shows unstaged or staged content differences. |
| `git log` | Displays recent commits and their messages. |

Staging selects changes for the next commit; committing saves a reviewed snapshot permanently in local history. The commit is not on GitHub until it is pushed.

### Git command glossary
- `git init`: initialise a Git repository.
- `git status`: inspect the current working tree.
- `git add`: stage selected changes.
- `git commit`: create a commit from staged changes.
- `git log`: view commit history.
- `git branch`: create or list branches.
- `git switch`: change the active branch.
- `git push`: publish local commits to a remote repository.
- `git pull` or `git fetch`: retrieve and/or integrate remote changes.

## 5. My understanding
A branch is an independent line of development that makes changes safer to isolate. A Pull Request presents branch changes for review and discussion before they are merged. These tools help multiple people work on the same project without immediately changing the shared main line.
